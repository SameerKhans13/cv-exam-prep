Problem 1: Convolution Output & Parameters

5 Marks

An input feature map of size 224 × 224 × 64 (H × W × C_in) is passed through a conv layer with 128 filters of kernel size 3 × 3, stride S = 2, padding P = 1, dilation D = 1, with bias.

W_out = ⌊(W - K_eff + 2P)/S⌋ + 1, where K_eff = D(K - 1) + 1
Params = (K × K × C_in + 1) × C_out
px
Step 1 (Output size):
K_eff = 1(3 - 1) + 1 = 3.
W_out = ⌊(224 - 3 + 2(1)) / 2⌋ + 1 = ⌊223 / 2⌋ + 1 = 111 + 1 = 112 px.
Step 2 (Parameters):
Weights per filter = 3 × 3 × 64 = 576. Add 1 bias = 577.
Total for 128 filters = 577 × 128 = 73,856 parameters.

Problem 2: RANSAC Required Iterations (Round Up!)

5 Marks

You are estimating a Homography between two images using matched keypoints. The outlier ratio is e = 0.50 (50% outliers). You want at least p = 0.99 (99%) probability of finding at least one outlier-free sample.

N = ⌈ ln(1 - p) / ln(1 - (1 - e)^s) ⌉
Note: For Homography, minimal sample size s = 4. Always round UP!
1. s = 4 (homography needs 4 point correspondences).
2. Inlier ratio = 1 - e = 0.50. Probability that all 4 are inliers = (0.50)^4 = 0.0625.
3. ln(1 - 0.99) = ln(0.01) = -4.60517.
4. ln(1 - 0.0625) = ln(0.9375) = -0.0645385.
5. Ratio = -4.60517 / -0.0645385 = 71.359.
6. Rounding: Always round UP $\to$ 72 iterations! (71 gets partial marks).

Problem 3: Intersection-over-Union (IoU) with Continuous Coords

5 Marks

Calculate the IoU between Box A: (10, 10, 50, 50) and Box B: (30, 30, 70, 70).
Convention: continuous coordinates (x1, y1, x2, y2), Area = (x2 - x1) * (y2 - y1), NO +1.

Intersection = (min(x2) - max(x1)) × (min(y2) - max(y1))
IoU = Inter / (Area_A + Area_B - Inter)
1. Area(A) = (50 - 10) × (50 - 10) = 40 × 40 = 1600.
2. Area(B) = (70 - 30) × (70 - 30) = 40 × 40 = 1600.
3. Overlap rect: x from max(10, 30)=30 to min(50, 70)=50 (width = 20).
   y from max(10, 30)=30 to min(50, 70)=50 (height = 20).
4. Inter = 20 × 20 = 400.
5. Union = Area_A + Area_B - Inter = 1600 + 1600 - 400 = 2800.
6. IoU = 400 / 2800 = 1/7 ≈ 0.143.

px m

Problem 5: Confusion Matrix & Class IoU / Dice

5 Marks

In a binary segmentation test, foreground pixels have: TP = 60, FP = 20, FN = 20.

IoU = TP / (TP + FP + FN)
Dice = 2·TP / (2·TP + FP + FN) = 2·IoU / (1 + IoU)
1. IoU = 60 / (60 + 20 + 20) = 60 / 100 = 0.60 (60%).
2. Dice = (2 × 60) / (2 × 60 + 20 + 20) = 120 / 160 = 0.75 (75%).
Sanity check: Dice = 2(0.60)/(1 + 0.60) = 1.20 / 1.60 = 0.75. Notice Dice (0.75) > IoU (0.60)!

Proof 1: Derivation of Dice = 2·IoU / (1 + IoU) and Proof that Dice ≥ IoU

4 Marks
1. Definitions:
Let $I = |A \cap B|$ (Intersection) and $U = |A \cup B| = |A| + |B| - I$ (Union).
$\text{IoU} = \frac{I}{|A| + |B| - I} \implies |A| + |B| - I = \frac{I}{\text{IoU}} \implies |A| + |B| = I\left(\frac{1}{\text{IoU}} + 1\right) = I\left(\frac{1 + \text{IoU}}{\text{IoU}}\right)$.

2. Substitute into Dice:
$\text{Dice} = \frac{2|A \cap B|}{|A| + |B|} = \frac{2I}{I\left(\frac{1+\text{IoU}}{\text{IoU}}\right)} = \mathbf{\frac{2\,\text{IoU}}{1 + \text{IoU}}}$. $\quad \blacksquare$

3. Proof of Inequality ($\text{Dice} \ge \text{IoU}$):
Consider the difference: $\text{Dice} - \text{IoU} = \frac{2\,\text{IoU}}{1 + \text{IoU}} - \text{IoU} = \frac{2\,\text{IoU} - \text{IoU}(1+\text{IoU})}{1 + \text{IoU}} = \frac{\text{IoU}(1 - \text{IoU})}{1 + \text{IoU}}$.
Since $\text{IoU} \in [0, 1]$, the numerator $\text{IoU}(1-\text{IoU}) \ge 0$ and the denominator $1+\text{IoU} > 0$.
Therefore, $\mathbf{\text{Dice} \ge \text{IoU}}$ always, with equality iff $\text{IoU} = 0$ or $\text{IoU} = 1$.

Proof 2: Why Essential Matrix E has 5 DOF while Fundamental Matrix F has 7 DOF

4 Marks
1. Fundamental Matrix F ($3 \times 3$, uncalibrated pixels $\mathbf{x}'^\top F \mathbf{x} = 0$):
• A $3 \times 3$ matrix has 9 raw parameters.
• Overall scale ambiguity removes 1 DOF (if $F$ satisfies the equation, so does $\lambda F$) $\implies 9 - 1 = 8$.
• Rank constraint: $\det(F) = 0$ (must have rank 2 to define epipoles as null-spaces) removes 1 constraint $\implies 8 - 1 = \mathbf{7\text{ DOF}}$.

2. Essential Matrix E ($E = [\mathbf{t}]_\times R$, normalized camera frame $\hat{\mathbf{x}}'^\top E \hat{\mathbf{x}} = 0$):
• $E$ is formed from relative rotation $R$ and translation $\mathbf{t}$.
• 3D rotation $R \in SO(3)$ has 3 DOF.
• Translation $\mathbf{t}$ has 3 components, but translation scale is unobservable from 2 images, so only its direction matters (unit sphere $S^2$) $\implies \mathbf{2\text{ DOF}}$.
• Total DOF = $3 + 2 = \mathbf{5\text{ DOF}}$.
• Singular value property: Two non-zero singular values must be equal, and the third is zero: $(\sigma, \sigma, 0)$.

Proof 3: Why DETR Eliminates NMS (Set Prediction & Hungarian Matching)

4 Marks
1. The Root Cause of NMS in Classical Detectors:
Prior detectors (Faster R-CNN, YOLO, SSD) place thousands of overlapping anchor boxes across grid cells. Multiple anchors fire on the same object, necessitating heuristic Non-Maximum Suppression (NMS) to greedily suppress duplicates based on an IoU threshold.

2. The DETR Paradigm: Direct Set Prediction:
• DETR uses a fixed small set of $N = 100$ learnable object queries passed through a Transformer decoder.
• The network directly predicts a set of $N$ bounding boxes and class logits.

3. Bipartite Matching Loss:
• Ground truth objects are padded with a background class $\varnothing$ up to size $N$.
• During training, the Hungarian Algorithm finds a global optimal 1-to-1 matching permutation $\hat{\sigma} \in \mathfrak{S}_N$ minimizing matching cost $\mathcal{L}_{match}$.
• Because each query can match at most one ground-truth object, two queries cannot both be assigned the same ground-truth object without incurring a severe penalty. Thus, duplicate detections are suppressed end-to-end without NMS.

Proof 4: Batch Normalization in Training vs Evaluation (Inference)

4 Marks
1. Training Mode (model.train()):
• Computes mean $\mu_B$ and variance $\sigma_B^2$ across the current mini-batch: $\mu_B = \frac{1}{m}\sum x_i$, $\sigma_B^2 = \frac{1}{m}\sum(x_i - \mu_B)^2$.
• Normalizes current batch: $\hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}}$, then scales and shifts: $y_i = \gamma \hat{x}_i + \beta$ ($\gamma, \beta$ are learnable).
• Updates running population statistics via Exponential Moving Average (EMA):
  $\hat{\mu} \leftarrow (1 - \rho)\hat{\mu} + \rho \mu_B$ and $\hat{\sigma}^2 \leftarrow (1 - \rho)\hat{\sigma}^2 + \rho \sigma_B^2$ (typically $\rho = 0.1$).

2. Evaluation / Inference Mode (model.eval()):
• Mini-batch statistics are NOT computed (batch size can even be 1).
• Fixed running statistics $\hat{\mu}$ and $\hat{\sigma}^2$ accumulated during training are used: $\hat{x} = \frac{x - \hat{\mu}}{\sqrt{\hat{\sigma}^2 + \epsilon}}$.
• Exam Trap: When freezing a pretrained CNN backbone with requires_grad = False, BN must still be set to eval() mode, otherwise running statistics continue to drift!
